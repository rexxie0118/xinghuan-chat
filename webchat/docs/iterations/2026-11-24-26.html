语义合并：LLM 判定同义记忆

词法 ≥0.90 直接合并；0.15–0.90 的同 kind 候选交给 LLM 判定同义； LLM 失败降级为不合并，不阻塞写入。consolidate 使用同一判定器。

状态：已完成 测试：105 项通过 架构：v37

为什么

我偏好简洁回答
回答请尽量简短

词法相似度低
但语义相同
→ 应合并为一条

实现

词法 ≥ 0.90       直接 duplicate
词法 0.15–0.90     同 kind 才调用 LLM
LLM 返回 same      合并
LLM 异常/否        保留两条

配置

WEBCHAT_MEMORY_SEMANTIC=off   # 默认
WEBCHAT_MEMORY_SEMANTIC=llm   # 开启

使用默认知识库的 chat provider
不调用 embedding API

验证

Fake judge:
  我偏好简洁回答
  回答请尽量简短
→ duplicate，只保留一条

LLM judge JSON 解析通过
105 tests passed

边界

  • LLM 只做二分类，不做聚类；
  • 只在词法候选范围内调用，真正的零重叠同义句可能漏掉；
  • LLM 失败默认不合并，保证不会误合并；
  • 会增加一次边界写入的延迟，默认关闭；
  • 未使用 embedding API，因为当前 DeepSeek 无 embedding endpoint。
