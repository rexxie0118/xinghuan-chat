文件更新时间作为制度版本参考

制度文档的生效月仍是第一优先级；文件的最后更新时间作为兜底： 没有生效月时用它判断新旧，同一生效月时用它做决胜。

状态：已完成 测试：129 项通过 架构：v50

规则

version key:
  effective_date or file_mtime_month
  + file_mtime as tiebreaker

1. 文档有明确生效月
   → 生效月优先

2. 没有生效月
   → 文件 mtime 兜底

3. 生效月相同
   → 较新的文件 mtime 胜出

4. 用户问历史/旧版
   → 保留多个版本

采集

ingest_file:
  path.stat().st_mtime
  → documents.meta_json.source_mtime

旧文档:
  bootstrap unchanged 时自动回填
  source_mtime

检索:
  document_modified_at(meta_json, source_uri)
  → 磁盘 stat 兜底

边界

  • 文件 mtime 可能因复制/解压/重新上传而改变，所以不能压过文档内明确生效月；
  • mtime 只精确到文件系统时间，不表达业务生效日；
  • 历史查询不会被过滤，仍可对比旧版；
  • 产品库仍有一份误传旧版，需单独删除。
