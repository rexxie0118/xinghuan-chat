SQLite → PostgreSQL 全量迁移

新增 pg_migrate：按外键顺序复制控制面 13 张表；支持 dry-run、upsert/skip、 行数校验。知识库 FTS/向量仍保留 SQLite，不在本次迁移范围。

状态：已完成 测试：114 项通过 架构：v40

迁移范围

users / sessions
conversations / messages
agents / agent_runs
user_runtimes / container_workspaces / container_checkpoints
user_memories / connectors / audit_events / department_agents

使用

python -m webchat.pg_migrate \
  --sqlite webchat/data/webchat.sqlite3 \
  --dry-run

WEBCHAT_DB_URL=postgresql://... \
python -m webchat.pg_migrate \
  --sqlite webchat/data/webchat.sqlite3 \
  --verify

行为

init_db → 创建/升级 Postgres schema
按 FK 顺序复制
默认 ON CONFLICT DO UPDATE
--mode skip → DO NOTHING
--verify → 目标行数不少于源
不打印 DSN/密码

兼容修复

  • 用户名查询从 COLLATE NOCASE 改为 LOWER()；
  • 记忆 MAX(a,b) 改为 CASE WHEN；
  • SCHEMA 补齐 user_memories 的 scope/agent/authority 字段；
  • 安装 psycopg[binary] 用于迁移。

验证

  来源行数统计正常

copy loop 使用 fake destination 验证
upsert/skip SQL 生成
114 tests passed

边界

  • 没有本地真实 PostgreSQL 实例，未做 live migration；
  • 知识库 kb_*.sqlite3 的 FTS/向量不迁移；
  • 迁移期间应停写，避免 SQLite 增量丢失；
  • 没有自动回滚/双写；
  • JSON/时间字段仍按 TEXT 存储。
