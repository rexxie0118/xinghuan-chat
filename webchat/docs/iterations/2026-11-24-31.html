队列可靠性：lease / retry / DLQ

Redis 队列从 ready+hash 升级为 ready/processing/dead：BLMOVE 进入 processing、 lease 超时回收、attempts/max_retries 重试、耗尽进入死信，并暴露队列深度指标。

状态：已完成 测试：118 项通过 架构：v42

状态机

ready
→ BLMOVE → processing
→ complete → completed（出 processing）
→ fail + attempts <= max → ready
→ fail + attempts > max → dead
→ lease expired → ready / dead

配置

WEBCHAT_JOB_MAX_RETRIES=3
WEBCHAT_JOB_LEASE_SECONDS=600
WEBCHAT_WORKER_ID=host:pid（可覆盖）

指标

/api/meta.queue
  ready
  processing
  dead

Job public:
  attempts
  max_retries
  status
  error

验证

fail attempt=1 → queued/retry
fail attempt=4 → dead
expired lease → requeued
idle BLMOVE timeout → None
118 tests passed

边界

  • 不是 exactly-once；长任务可能重复执行；
  • lease 600s，超过 lease 的任务可能被其他 Worker 重派；
  • 没有任务优先级；
  • 多 Worker 尚未压测；
  • 死信没有管理 UI。
