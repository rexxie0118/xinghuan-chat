Agent 记忆系统：趋势与 backlog

截至 2026-11-24 的公开资料与工程实践。结论是：记忆正在从“向量库 + top-k” 变成“分层 + 时间/冲突 + 治理 + 评测”的工程系统；Context/Compaction 不等于 Memory。

类型：研究笔记 资料：ACL/EMNLP 2026 + 厂商工程实践 对应实现：v34 scope / provenance

一句话结论

Context / Compaction  → 服务当前任务
Memory                → 服务未来任务

未来竞争力不在“记得更多”，
而在“写得准、选得对、可追溯、能遗忘、可评测”。

趋势

趋势变化成熟度
Context 与 Memory 分家 Compaction 保留当前工作状态；Memory 只保留跨任务可复用经验，不把记忆当事实数据库。 生产可用
混合记忆 向量做语义召回，图谱做关系/时间，SQL 做精确字段和权限，文件做可导出/可审阅。 生产模式，复杂度高
时间与冲突 valid_from / valid_to、superseded_by、[CURRENT] 标记；过期事实降权而不是简单覆盖。 研究到早期生产
可审计记忆 scope、来源、导出、回滚、删除、并发写、审计日志成为企业记忆的一部分。 企业产品化中
选择优于抽取 严格上下文预算下，从候选中选少量高价值记忆，比无限抽取更有效。 生产可用
评测升级 从“记住事实”转向隐式约束、权限、来源、冲突、保留期等操作级正确性。 快速演进
多 Agent 共享记忆 共享档案不够；需要角色可见性、写入者权威、来源和保留策略。 早期
多模态 / 可移植记忆 文件式、跨 Agent、跨平台记忆出现，但还不是第一优先级。 早期

关键证据

  • Context ≠ Memory： OpenAI Agents SDK 把 compaction 和 memory 拆开：compaction 让当前长任务继续， memory 复用跨任务的工作流经验；记忆不应成为调查结论的 system of record。 OpenAI Cookbook
  • 文件式、可审计记忆： Anthropic 的 Managed Agents Memory 以文件挂载，支持导出、API、审计、回滚、脱敏、 按 scope 共享，以及多 Agent 并发访问。 Claude Managed Agents Memory
  • 时间知识图谱： RoMem 用连续相位旋转区分“高频变化关系”和“稳定事实”，让过期事实降权而非删除； 在时序推理上报告 2–3× MRR/准确率提升。 EMNLP 2026 · RoMem
  • 协作记忆： COLLABMEM 指出共享档案不足，正确性还要求信息到达正确角色、对未授权角色隐藏、 来源正确、按权威性解决冲突、按保留策略更新；TMS-GRAPH++ 使用角色过滤视图和 [CURRENT] 标记。 EMNLP 2026 · COLLABMEM
  • 隐式约束评测： LoCoMo-Plus 评估“用户早期说的目标/状态/价值观，在后续 cue 出现时能否被正确应用”， 而不是只评估表面事实回忆。 ACL 2026 · LoCoMo-Plus
  • 评测可复现性： LoCoMo 类对比会受 embedder、judge、query set、seed 影响；单一排行榜不能代替业务评测。 2026 · LoCoMo comparison （预印本）
  • 2026 综述： Forms × Functions × Dynamics 的 3×3×3 分类整理了约 200 篇论文， 说明记忆已经是完整系统设计问题。 Agent Memory Research in 2026 （预印本）

注：Zenodo 条目和厂商博客不是同行评审结论；ACL/EMNLP 论文也可能存在实验范围限制。 这里把它们作为趋势证据，不作为绝对排名。

哪些是噪音

  • “无限记忆”：上下文、延迟、噪声和成本都有上限。
  • “向量库就是记忆系统”：向量库只是召回层，缺少写入策略、冲突、权限、审计和遗忘。
  • “全自动写入”：prompt injection、错误结论固化、隐私泄漏和跨用户污染风险高。
  • “单一 benchmark 排名”：记忆评测对实现细节非常敏感，必须配合业务回归集。

Backlog

优先级事项验收标准状态
P0 记忆写入质量 低置信度跳过；近重复合并；同槽位 valid_to/superseded_by；召回预算。 完成 · v33
P1 记忆 scope personal / department / org 三级；读取按角色过滤；写入有明确 owner。 完成 · v34
P1 provenance 每条记忆有 source_uri、source_message_id、evidence_snippet、created_by、valid_from。 完成 · v34
P1 审核与审计 pending → approve/reject；delete 保存 snapshot，可 undo；create/delete 都写 audit_events。 完成 · v35
P1 记忆整理任务 后台定期 consolidation；当前只处理个人记忆，尚未做 dry-run/导出确认。 基础完成 · v35
P2 记忆评测集 覆盖早期约束、过期记忆、冲突事实、越权访问、来源正确性；接入 CI。 待办
P2 语义合并 用 embedding 或 LLM 对候选记忆做语义聚类，替代纯词法近重复。 待办
P3 团队/多 Agent 记忆 部门共享记忆、角色过滤视图、写权限、权威性冲突解决。 待办
P4 时间知识图谱 / 多模态 仅在业务确有时序或多模态需求时投入；不做“为了架构而架构”。 待办

建议顺序

P1 治理        scope ✅ → provenance ✅ → approval ✅ → audit rollback ✅ → consolidation job ✅
P2 评测        constraint / stale / conflict / access / provenance
P3 协作        department memory → role views → write authority
P4 高级能力    时间 KG / 多模态 / 语义聚类（按需）

不建议现在直接上复杂时间知识图谱。对星环 Chat 当前阶段， scope、来源、审计、评测的收益远高于增加存储形态。
